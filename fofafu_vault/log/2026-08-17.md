## 2026-08-17

- [engineering] User reported a CORS error saving a profile edit at `https://fofafu-frontend.vercel.app/family/me`. Root-caused live against production: `edgeRequest()` (`frontend/src/api/edgeClient.ts`, part of [[features/migrate-render-to-vercel-supabase]]) forwards the caller's Supabase session token as `Authorization` but never sends the project's `apikey` header. Confirmed via direct `curl` against `rlizubjugevyxsfzmpny.supabase.co/functions/v1/family/me`: without `apikey` the gateway rejects with `401 UNAUTHORIZED_NO_AUTH_HEADER` before the request reaches the function (no `x-deno-execution-id`); with `apikey` it reaches the function code. This affects every `edgeRequest` call in production — family, announcement, community, and search — not just the save-profile path. Note: CORS headers (`Access-Control-Allow-Origin: *`) were present on both the gateway rejection and the preflight in testing, so the failure is a silent 401 rather than a literal browser-blocked CORS error in the general case — worth asking the user for the exact console text if a genuine CORS block still reproduces after this fix. Wrote a failing test first (`edgeClient.test.ts`), confirmed red, fixed by exporting `SUPABASE_ANON_KEY` from `supabaseClient.ts` and sending it as `apikey` on every edge request. Frontend suite 135/135, `tsc --noEmit` clean. PR #59 (draft) against master.
